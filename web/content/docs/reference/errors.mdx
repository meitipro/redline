A refused write still reaches consensus: validators agree the refusal is the right result, and the transaction reads ACCEPTED. The site counts a write as done only when the status is ACCEPTED or FINALIZED **and** the execution returned; otherwise it shows the sentence below, which the transaction carries in its result payload.

`[EXPECTED]` refusals are deterministic and identical on every validator. `[LLM_ERROR]` means the scope judge's answer could not be read, even after one retry; validators then disagree on purpose, so the round rotates to a committee that can answer, and nothing defaults to a verdict.

A rejected attack is not a refusal: an attack that is too long or holds a canary-shaped string is stored as `REJECTED`, with its reason, and its fee is refunded through `claim`.
